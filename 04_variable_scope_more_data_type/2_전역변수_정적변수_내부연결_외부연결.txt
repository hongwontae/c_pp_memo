** 선언은 header / 정의는 실제 cpp 파일 **
** 컴파일 header에 영향 / 링킹은 연결에 영향 **

1. 전역 변수
    1-1. 함수 외부에서 선언한 변수를 전역 변수라고 합니다. -> 일반적으로 모든 곳에서 접근 가능
    1-2. 전역 네임스페이스는 전역 영역입니다.
        => c++에서 좀 더 정확하게 구분하기 위해 전역 네임스페이스라는 용어를 사용합니다.
    1-3. 지역 scope에서 :: value_name을 사용하면 전역에 접근할 수 있습니다.


2. 정적 변수 (static)
    2-1. 전역 정적 변수
        => 전역 변수지만 다른 파일에서 접근할 수 없습니다.
    2-2. 정적 변수
        => 함수 내부에서 선언된 정적 변수입니다.
        => 함수 내부에서만 접근이 가능하고 생명주기가 전역입니다.
        

3. extern 키워드
    3-1. C++에서는 각각의 .cpp 파일을 독립적으로 컴파일합니다.
    3-2. 예시
        int a = 10;
        int main() {
            return 0;
        } // main.cpp

        #include <iostream>
        void test() {
            std::cout << a;
        } // test.cpp
    
    3-3. 3-2 처럼 컴파일하면 test.cpp에서 컴파일 오류가 발생합니다.
        => 컴파일러가 test.cpp를 컴파일할 떄 main.cpp에 어떤 코드가 작성되어 있는지 자동으로 알지 못하기 때문입니다.
    
    3-4. 3-3 같은 동작 떄문에 extern을 사용합니다.
        #include <iostream>
        extern int a;
        void test() {
            std::cout << a;
        }
    
    3-5. 이제 컴파일러는 a가 int 타입 변수라는 사실을 알게됩니다.
        => 실제 정의를 모르더라도 컴파일 할 수 있습니다.
    
    3-6. 컴파일러가 a라는 사실을 알고 컴파일하고 링커가 a의 실제 정의를 찾아 연결하는 것입니다.

    3-7. main.cpp의 int a와 test.cpp의 extern int a는 동일한 변수입니다.


4. 함수를 선언할 떄 extern 키워드가 보이지 않게 붙어 있습니다.
    => 그래서 header 파일에서 함수를 선언할 떄 외부에서 사용할 수 있습니다.


5. 컴파일 시점과 링킹 시점에 따른 해석
    5-1. header 파일을 include 하는 것은 컴파일 시점에 필요합니다.
    5-2. 연결을 하는 것은 링킹 시점에 필요합니다.


6. 정리
    => extern 키워드는 선언과 관련 있으며, header 파일과 관련있습니다.
    => 컴파일 성공을 위해 선언이 필요하며, 가져오기 위해서는 extern 키워드가 필요합니다.
    => header 파일에 int a; 이렇게만 존재하고 다른 파일들에서 a를 사용하려고 하면 전역 변수가 아니라
        그 파일이 내부의 int a가 되는 것입니다. (지역 변수 int a)
