1. 인라인 함수
    => 함수 호출에 의한 오버헤드를 줄이기 위해 도입된 기능입니다.
    => 일반 함수 호출 시 -> CPU가 함수의 명령어 위치로 이동 -> 연산 실행 -> 결과 반환 -> caller의 위치로 복귀
    => 이러한 함수 호출과 복귀에는 비용이 발생하고 이를 함수 호출에 의한 오버헤드라고 합니다.


2. 인라인 함수 문법
    => inline 반환_타입 함수명 () {}


3. 인라인 함수 개념
    3-1. 인라인 확장이 적용되면 컴파일러는 실제 함수 호출대신, 함수의 연산을 호출한 위치에 직접 배치할 수 있습니다.
        => 이렇게 확장이 되면 별도의 함수 호출과 복귀가 필요하지 않을 수 있습니다.
    
    3-2. inline을 선언했다고 해서 컴파일러가 반드시 인라인 확장하는 것은 아닙니다.
        => 컴파일러가 함수의 크기, 최적화 설정, 호출 상황 등을 고려해서 직접 판단합니다.


4. 일반 함수는 여러 .cpp에 똑같이 정의하면 문제 발생 -> 인라인 함수는 특정 조건에서 이를 허용합니다.
    4-1. MyProject/
        ├── main.cpp
        ├── test.cpp
        └── math.h
    
    4-2.  
    math.h
    #pragma once

    int add(int a, int b) {
        return a + b;
    }

    main.cpp
    #include "math.h"

    int main() {
        int result = add(10, 20);
        return 0;
    }

    test.cpp
    #include "math.h"

    int test() {
        return add(30, 40);
    }

    4-3. 컴파일러는 전처리할 떄 헤더의 내용을 상단에 포함시킵니다.
        => main.cpp에도 add() 함수의 정의가 존재하고, test.cpp에도 add() 함수의 정의가 존재합니다.
        => 동일한 이름과 매개변수를 가진 함수가 두 번 정의된 상태입니다.
    
    4-4. 컴파일러는 각각의 .cpp 파일을 이러한 전처리 + 컴파일 이후 두 개의 목적 파일이 생성합니다.
    
    4-5. 링킹 단계에서 main.obj, test.obj를 합치는 과정에서 중복된 외부 함수 정의가 존재합니다.
        => C++에는 **ODR(One Definition Rule, 단일 정의 규칙)**이라는 규칙이 존재
        => 현재는 add()가 두 번 정의되어 있으므로 이 규칙을 위반
        => 링킹 오류가 발생합니다.
    
    4-6. math.h의 add 함수에 inline을 붙입니다.
        => 각 번역 단위에서
        inline int add(int a, int b) {
            return a + b;
        } 정의가 들어갑니다.
    
    4-7. 중복 정의로 인한 링크 오류가 발생하지 않습니다.
        => C++ 언어 규칙이 inline 함수에 대해서는 여러 번역 단위에 동일한 정의가 존재하는 것을 허용합니다.
        => 이 떄 아래 조건을 만족해야 합니다.
            1. 함수 정의가 여러 번역 단위에서 동일해야 한다.
            2. 각 번역 단위에서 인라인 함수의 정의를 볼 수 있어야 한다.
            3. 그 밖의 ODR 조건도 만족해야 한다.
    
    4-8. pragma once는 하나의 번역 단위에서 같은 헤더가 여러 번 포함되는 것을 방지
        => main.cpp, test.cpp는 다른 번역 단위입니다.
