1. 2의 보수
    1-1. 보수란 어떤 기준값을 만들기 위해 부족한 만큼 채워 주는 수입니다.
    1-2. 컴퓨터에서 2의 보수의 2는 2진법을 의미합니다. -> 숫자 2를 더하거나 빼는 개념이 아닙니다.
    
    1-3. 십진법 10의 보수
        => 3 + x = 10 -> 7을 3에 대한 10의 보수라고 합니다.
        => 25 + 75 = 100 -> 75를 25에 대한 10의 보수
        => 100의 보수가 아니라 10의 보수일까?
        => 10 진법은 한 자릿수에서 10, 두 자릿수에서 100, 세 자릿수에서 1000을 기준으로 합니다.
    
    1-4. 컴퓨터의 2의 보수
        => 2진법에서는 한 자리가 올라갈 때마다 값이 2배가 됩니다.
        => 10 (2), 100 (4), 1000 (8), 10000 (16)
        => 4비트 숫자 0101, 어떤 이진수를 더해야 10000이 되는가? -> 1011
        => 이 떄 1011을 0101에 대한 2의 보수라고 합니다.
        => 2진법에서는 10, 100, 1000, 10000처럼 2의 거듭제곱을 기준으로 보수를 구합니다.
    
    1-5. 컴퓨터의 2의 보수 +
        => 2의 보수는 비트 수에 따라 달라집니다.
        비트 수	    1의 이진수	        1의 2의 보수
        4비트	    0001	           1111
        8비트	    00000001	       11111111
        16비트	    0000000000000001   1111111111111111
        => 결국 n 비트 수에서 2의 보수를 구한다는 것은 그 수에 더해서 2^n이 되는 수를 구하는 것

    1-6. 컴퓨터의 2의 보수 ++
        => signed char a = -5;이 어떻게 컴퓨터에 저장되는 흐름
        => 8비트에서 양수 5의 이진법 표기 -> 0000 0101
        => ~0000 0101 -> 1111 1010
        => 1111 1010 + 1 -> 1111 1011
        => signed char는 마지막 비트가 -128을 의미합니다.
        => -128 + 64 + 32 + 16 + 8 + 2 + 1 = -5; -> 표현 완료
        => 0000 0101 + 1111 1010 -> 1 0000 0000 -> 2의 보수 확인 완료
        => 0000 0101의 2의 보수는 1111 1010이다.


2. 2의 보수 +
    2-1. 연산을 할 떄 피연산자들은 일반적으로 정수 승격된 뒤에 계산에 들어갑니다.
        => unsigned char a = 1, b = 1, c = 1;
        => unsigned char d = a + b;
        => 32비트 1인 a와 32비트 1인 b가 더해지고 unsigned라서 가장 오른쪽부터 1byte만 전달합니다.
    
    2-2. 비트 플래그와 ~ 연산자 
        => unsigned char flags = 0b 0000 0101;
        => auto result = ~flags;
        => 00000000 00000000 00000000 00000101
        => 11111111 11111111 11111111 11111010
        => -6

        => std::uint32_t flags = 0b00000101; -> unsigned int 타입
        => auto result = ~flags;
        => 00000000 00000000 00000000 00000101
        => 11111111 11111111 11111111 11111010
        => 4294967290

        => auto에 저장하는게 아니라 unsinged char에 다시 들어가야 원하는 값을 얻을 수 있습니다.
        => 연산 결과가 32비트를 뒤집은 값이라 하더라도 char에 넣으면 가장 오른쪽부터 1byte만 들어가기 때문입니다.
